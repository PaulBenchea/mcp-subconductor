# Subconductor - LLM Agent Rules

Welcome, AI Agent. If you are reading this, you are operating within the Subconductor repository. Subconductor is an MCP (Model Context Protocol) server designed to act as a persistent state machine for AI workflows.

To ensure consistency, code quality, and security, you **MUST** strictly adhere to the following rules during your execution:

## 1. Coding Standards
- **No Comments**: Do NOT add inline explanatory comments to the source code. The code must be self-documenting.
- **No Abbreviations**: You must use fully spelled-out variable names.
  - ❌ `err`, `e` -> ✅ `error`
  - ❌ `idx`, `i` -> ✅ `index`
  - ❌ `c`, `col` -> ✅ `column`
  - ❌ `req`, `res` -> ✅ `request`, `response`
- **Strict Typing**: Avoid the `any` type in TypeScript. Infer types or define explicit interfaces.

## 2. Architecture & State
- All checklist state must utilize the enums defined in `src/models/enums.ts` (e.g., `ChecklistStatus.Active`, `ChecklistStatus.Idle`). Do not use magic strings or bracket prefixes like `[x]` internally.
- IDs are **monotonic and immutable**. Do not write logic that re-indexes task IDs after a deletion.

## 3. Git & Commits
- You must use the following commit message format: `[scope][subscope] Description` or `[scope] Description`.
- **Scope**: Represents the area of the codebase being modified (`app`, `services`, `tools`, `models`, `docs`).
- **Subscope** *(optional)*: Provides more context (e.g., `[tools][task]`).
- **Description**: Capitalized, imperative tone, NO trailing period.
- *Examples*: 
  - `[services] Implement monotonic task IDs`
  - `[models][enums] Add ChecklistStatus enum`

## 4. Development Cycle
- Always run `npm run build` after making modifications to TypeScript files to ensure the `dist` folder is updated, as MCP clients rely on the compiled output.
